Providers

Whether each CLI can be started. That is not the same as being signed in — every one of them starts happily while logged out. Check sign-in sends each a one-word prompt, which only a real session can answer. It costs a trivial amount of quota, which is why it is a button.

Repositories to Scan

Add up to 16 separate repositories. Each uses the models, bug areas and path scope below. Three repositories can be active; Claude reviews as many areas at once as the session limit below allows, and every other provider reviews one at a time across the batch. Stop stops the whole batch. To remove a repository, delete its line.

Claude only. Its reviews are separate processes that share nothing, so several can run together; the limit that matters is your own Claude rate limit, which BugSleuth cannot see. Set it too high and sweeps fail after waiting rather than sooner. Every other provider reviews one area at a time because its CLI shares one signed-in session on disk.

Fix repositories

Choose a provider and model for each scanned repository, then start its fixes. Up to three Codex instances can fix separate repositories at the same time. Other providers run one fix at a time each. Start another repository while fixes are running; Stop all fixes cancels active and queued jobs.

Or have a model apply them here. It is given the same prompt the Copy button hands you, with write access to this repository: it edits files in place, runs your tests, and commits as it goes.

Nothing it writes has been checked by anyone — a finding can be confidently wrong, and a fix for one is a change you did not want. BugSleuth refuses to start unless the working tree is clean, so every edit shows up in git diff and git log. Read them before you keep them.
