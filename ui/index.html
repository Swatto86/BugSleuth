Proof

A finding is a model's claim, and a well-written wrong one reads exactly like a real one. Proving is how a claim becomes evidence: BugSleuth copies your repository to a throwaway checkout, records which of your tests already pass, then asks a model to write a test that fails because of the defect — not to fix it.

Then BugSleuth runs the tests itself and watches. It calls a defect proved only when the new test fails, every test that passed before still passes, and that named test fails on its own. A model can describe a bug that is not there; it cannot write a test that genuinely fails for a reason that does not exist. Requiring the old tests to still pass is what stops it "proving" a defect by quietly breaking your code.

It is the expensive part — one model call and up to three full test runs per defect — which is why it is off unless you ask.

Proving runs the reviewed repository's own build and test commands on this machine, with your permissions and no sandbox. A build script or test fixture in that code executes as you. The throwaway checkout stops it changing the code under review and nothing else — so only ask for proof on a repository you would already be willing to run.

Result

Or have a model apply them here. It is given the same prompt the Copy button hands you, with write access to this repository: it edits files in place, runs your tests, and commits as it goes.

Nothing it writes has been checked by anyone — a finding can be confidently wrong, and a fix for one is a change you did not want. BugSleuth refuses to start unless the working tree is clean, so every edit shows up in git diff and git log. Read them before you keep them.
